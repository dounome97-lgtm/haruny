# 개발시 발생한 문제들

이 문서는 개발 중 실제로 겪은 문제와, 다음 설계/구현 때 미리 챙겼어야 할 고려사항을 남기는 기록이다.
단순 회고가 아니라 다음 작업 품질을 올리기 위한 재발 방지 문서로 사용한다.

## 사용 방식

- 문제가 생기면 `무슨 일이 있었는지`, `왜 생겼는지`, `다음에는 무엇을 먼저 요구/확인할지`를 짧게 남긴다.
- 설계 단계에서 미리 챙겼어야 할 조건도 여기에 추가한다.
- 이미 해결된 문제라도, 다음 화면이나 기능에서 반복될 수 있으면 기록한다.
- 90번 작업 기억 문서에는 현재 판단에 꼭 필요한 압축 요약만 남기고, 자세한 문제 기록은 이 문서에 둔다.

## 001. 시안 PNG만으로 구현을 시작해 이미지 품질이 떨어짐

### 발생한 문제

- 최초 시안이 화면 전체 PNG 중심으로 만들어졌다.
- 구현 과정에서 일러스트와 아이콘을 코드/SVG로 비슷하게 다시 그리거나, 나중에 시안 PNG에서 crop해야 했다.
- 그 결과 얼굴, 노트, 버튼 아이콘 같은 시각 요소의 품질이 시안보다 떨어졌다.
- 구현된 화면이 확정 시안과 달라 보였고, 사용자가 직접 비교하면서 품질 차이를 발견했다.

### 원인

- 시안 생성 단계에서 `구현 가능한 디자인 handoff 자료`를 요구하지 않았다.
- 전체 화면 미리보기 PNG만 있고, 개별 asset, 투명 배경 파일, Figma형 스펙이 없었다.
- 카드 높이, 폰트 크기, line-height, 여백, radius, shadow 같은 수치 스펙이 충분히 분리되어 있지 않았다.
- 텍스트로 구현해야 할 영역과 이미지 asset으로 들어가야 할 영역이 명확히 구분되지 않았다.

### 다음에는 이렇게 요청해야 함

```text
단순 PNG 목업만 만들지 말고, 실제 구현 가능한 디자인 스펙으로 만들어줘.

필수 산출물:
1. 화면 전체 PNG 미리보기
2. 각 일러스트/아이콘을 개별 asset으로 분리
   - 투명 배경 PNG 또는 SVG
   - 파일명과 사용 위치 명시
3. Figma 스타일 스펙 문서
   - 화면 폭 기준
   - 여백, 카드 높이, radius, shadow
   - 폰트 크기/굵기/line-height
   - 색상 토큰
4. 컴포넌트 단위 분해
   - Header
   - MissionCard
   - ActionButton
   - SummaryCard 등
5. 텍스트가 실제 HTML로 들어갈 영역과 이미지로 들어갈 영역을 구분
6. 모바일 390px 기준에서 줄바꿈이 생기지 않아야 하는 문구 표시
```

더 직접적인 요청 예:

```text
이 시안은 나중에 Next.js/Tailwind로 구현할 거야.
그래서 예쁜 이미지 한 장이 아니라, 구현자가 그대로 옮길 수 있는 디자인 패키지로 만들어줘.
전체 화면 PNG와 함께, 캐릭터/아이콘/일러스트는 모두 개별 투명 PNG asset으로 분리하고,
카드 크기, 여백, 폰트 크기, 색상, radius, shadow 값을 문서로 같이 줘.
```

### 앞으로의 기준

- 시안은 `목업 이미지`가 아니라 `디자인 handoff 패키지`로 받는다.
- 일러스트는 처음부터 개별 투명 PNG/SVG asset으로 export한다.
- 시안 원본 asset이 없고, 코드로 재현했을 때 품질이 떨어지면 억지 재그림보다 시안 crop asset을 우선 사용한다.
- 단, crop asset은 임시 또는 1차 MVP용으로 기록하고, 장기적으로는 원본 asset/Figma export로 교체할 수 있게 경로와 용도를 문서화한다.

## 002. 모바일 폭에서 글자가 커져 카드/버튼 안에서 넘치거나 줄바꿈됨

### 발생한 문제

- 시안과 비교했을 때 버튼 안 글자, 카드 제목, 요약 숫자가 과하게 커졌다.
- 일부 문구가 테두리 안에서 줄바꿈되거나, 카드 내부 여백 없이 붙어 보였다.
- `남은 시간` 같은 짧은 라벨도 모바일 폭에서 세로로 꺾여 보이는 문제가 있었다.

### 원인

- 시안의 실제 모바일 기준 폭과 구현 화면의 container/padding/gap 차이를 충분히 계산하지 않았다.
- 글자 크기만 시안 분위기에 맞추려 했고, 실제 버튼 칸 폭 안에서 `아이콘 + gap + 텍스트 + 좌우 padding`이 들어가는지 먼저 검증하지 않았다.
- `whitespace-nowrap`만 넣으면 해결된다고 봤지만, 실제로는 font-size, icon size, padding, grid column 폭을 함께 조정해야 했다.

### 앞으로의 기준

- 모바일 화면은 최소 390px 기준으로 먼저 확인한다.
- 버튼/카드 내부 텍스트는 다음 합산 폭을 먼저 계산한다.
  - 좌우 padding
  - 아이콘 width
  - icon-text gap
  - 가장 긴 텍스트 width
- 한 줄 유지가 중요한 문구는 `whitespace-nowrap`를 쓰되, 동시에 작은 화면용 font-size와 icon-size를 별도로 둔다.
- 시안보다 글자가 커지면 더 좋아 보이는 것이 아니라, 카드 구조가 무너질 수 있으므로 시안보다 과한 확대를 피한다.
- 버튼 안 글씨는 좌우에 숨 쉴 여백이 있어야 하며, 여백을 만들 수 없으면 글자/아이콘을 줄인다.
