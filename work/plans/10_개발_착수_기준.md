# 개발 착수 기준

## 목적

이 문서는 1차 MVP 개발을 시작하기 전에 확정한 기준이다.
개발 중 판단이 흔들릴 때는 이 문서를 우선 확인한다.

## 기술 스택

1차 MVP는 빠른 화면 검증과 로직 검증을 위해 웹앱으로 시작한다.
다만 최종적으로 모바일 앱 전환을 전제로 하므로, 핵심 로직은 플랫폼 독립적으로 분리한다.

- 프레임워크: Next.js
- 언어: TypeScript
- 스타일: Tailwind CSS
- 초기 데이터: mock 데이터
- 초기 인증: 실제 로그인 없이 mock 사용자
- 초기 DB: 사용하지 않음
- 이후 DB 후보: Prisma + SQLite 또는 PostgreSQL
- 이후 앱 전환 후보: React Native 또는 Flutter

## 1차 MVP 범위

1차 MVP는 다음 기능으로 고정한다.

- 학생용 `오늘` 화면
- 학생용 `이번 주` 화면
- 부모용 `시험 준비 만들기`
- 부모용 `평시 루틴 만들기`
- 장기 계획에서 오늘 공부 자동 생성
- 공부 시작/완료 체크
- 남은 시간 계산

## 1차 MVP 제외 범위

다음은 1차 MVP에서 구현하지 않는다.

- 실제 푸시 알림 연동
- 위치 추적
- 휴대폰 사용 시간 수집
- AI 자유 대화
- 고급 통계
- 결제/구독
- 교사용 또는 학원용 관리자 기능
- 앱스토어/플레이스토어 배포
- 실제 DB/인증 고도화

## 개발 순서

1차 개발은 화면을 먼저 만들고, 계산 로직을 점진적으로 붙인다.
이 앱은 사용자가 실제로 열고 움직일 수 있는 경험이 중요하므로, 학생용 `오늘` 화면을 가장 먼저 만든다.

1. 학생용 `오늘` 화면
2. 학생용 `이번 주` 화면
3. 부모용 `시험 준비 만들기`
4. 부모용 `평시 루틴 만들기`
5. 장기 계획에서 오늘 미션 생성 로직
6. 공부 시작/완료 체크
7. 남은 시간 계산

## 구조 원칙

모바일 앱 전환을 위해 다음 구조를 지킨다.

- UI 컴포넌트 안에 계획 계산 로직을 넣지 않는다.
- 장기 계획 생성 로직은 별도 모듈로 둔다.
- 하루 코치/남은 시간 계산 로직은 별도 모듈로 둔다.
- mock 데이터도 실제 API 응답처럼 사용할 수 있는 형태로 만든다.
- 학생/부모 화면은 서비스 계층에서 데이터를 받아 표시한다.
- 알림은 아직 실제 발송하지 않지만, `학생 알림`, `부모 알림` 인터페이스를 염두에 둔다.
- 브라우저 전용 기능에 핵심 로직이 의존하지 않게 한다.

## 화면 우선 개발 원칙

- 첫 화면은 학생의 `오늘` 화면이다.
- 관리 메뉴나 테이블이 첫 화면에 나오면 실패로 본다.
- 학생 화면은 시간표보다 `지금 할 미션`을 먼저 보여준다.
- 오늘 계획은 필수, 추가, 남으면 미션으로 나눈다.
- 부모 화면은 상세 로그보다 계획 생성과 현실성 판단을 우선한다.
- 모든 화면은 모바일 너비에서 먼저 자연스러워야 한다.

## 첫 개발 완료 기준

첫 개발 단위는 다음 조건을 만족하면 완료로 본다.

- 학생이 `오늘` 화면에서 지금 할 미션을 바로 볼 수 있다.
- 오늘 미션이 필수, 추가, 남으면으로 구분된다.
- 남은 공부 시간과 남은 가용 시간이 표시된다.
- `시작하기`, `끝냈어요` 흐름이 동작한다.
- 화면이 백오피스가 아니라 생활형 코치 앱처럼 느껴진다.
- 핵심 계산 로직이 UI에서 분리되어 있다.

## 검증 방식

작은 화면/문구 수정은 관련 파일 확인으로 끝낸다.
계산 로직, 라우팅, 상태 관리, 공통 컴포넌트를 수정한 경우에만 전체 빌드 또는 통합 검증을 우선 고려한다.

1차 MVP 개발 중에는 다음 대표 시나리오를 계속 확인한다.

- 한 달 시험 계획 시나리오
- 주간 총량 보정 시나리오
- 일일 미션 방식 시나리오
- 오늘 계획 지연 후 회복 시나리오
