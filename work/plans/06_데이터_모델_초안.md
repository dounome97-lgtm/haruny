# 데이터 모델 초안

## 모델링 원칙

MVP 데이터 모델은 장기 학습 목표를 주간/일간 계획으로 분해하고, 하루 계획과 실행 기록을 정확히 표현하는 데 집중한다.
감시성 데이터인 위치, 휴대폰 사용 기록은 MVP에서 제외한다.

## 주요 엔티티

## Family

가족 단위 계정이다.

| 필드 | 설명 |
|---|---|
| id | 가족 ID |
| name | 가족 이름 |
| created_at | 생성 시각 |

## User

부모 또는 학생 사용자다.

| 필드 | 설명 |
|---|---|
| id | 사용자 ID |
| family_id | 가족 ID |
| role | parent 또는 student |
| name | 이름 |
| timezone | 시간대 |
| created_at | 생성 시각 |

## StudentProfile

| 필드 | 설명 |
|---|---|
| id | 프로필 ID |
| user_id | 학생 사용자 ID |
| default_wake_time | 기본 기상 시각 |
| default_sleep_time | 기본 취침 시각 |
| school_start_time | 기본 등교 시각 |
| school_end_time | 기본 하교 시각 |

## DayPlan

| student_id | 학생 사용자 ID |

## 핵심 관계

- Family 1:N User
- User 1:1 StudentProfile
- User 1:N DayPlan
- User 1:N LongTermStudyPlan
- LongTermStudyPlan 0:1 ExamSchedule
- ExamSchedule 1:N ExamSubject
- LongTermStudyPlan 1:N RoutineRule
- LongTermStudyPlan 1:N WeeklyStudyPlan
- WeeklyStudyPlan 1:N WeeklySubjectAllocation
- DayPlan 1:N StudyTask
- DayPlan 1:N TimeBlock
- StudyTask 1:N StudySession
- DayPlan 1:1 CoachState
- DayPlan 1:N NotificationEvent
- DayPlan 1:N PlanAdjustmentRequest

## 계산에 필요한 입력

- 현재 시각
- 장기 계획의 시작일과 종료일
- 시험일과 시험일차별 과목
- 과목별 목표 공부 시간 또는 중요도
- 요일별 반복 루틴
- 남은 StudyTask의 estimated_minutes 합계
- 현재 시각 이후의 TimeBlock 중 is_study_available 값
- 고정 일정의 시작/종료 시각
- StudySession의 시작/완료 상태

## 장기 계획 생성 규칙

- 시험 대비기간은 기본적으로 시험 시작일 한 달 전부터 시작한다.
- 시험일이 가까운 과목일수록 시험 직전 주의 복습 비중을 높인다.
- 과목별 총 공부 시간은 중요도, 시험일, 남은 기간을 기준으로 주간 배분한다.
- 요일별 가용 시간이 부족한 날은 자동으로 부담도를 낮춘다.
- 평시 루틴은 시험 대비기간에 축소하거나 시험 과목 중심으로 재배치한다.
- 생성된 DayPlan과 StudyTask는 사용자가 조정할 수 있어야 한다.

## MVP에서 보류할 데이터

- 실시간 위치 좌표
- 휴대폰 앱별 사용 시간
- 음성 녹음 또는 대화 원문
- 상세 학습 성적
- 외부 학원/학교 연동 데이터

## 주의 사항

민감한 학생 데이터는 최소 수집을 원칙으로 한다.
부모에게 제공하는 정보는 상세 감시 로그보다 상태 요약 중심으로 설계한다.
