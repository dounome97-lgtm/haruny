# Codex 작업 기억

이 문서는 Codex가 작업 시작 전에 먼저 읽는 압축 컨텍스트다.
사용자용 회의록이나 채팅 원문 보관 문서가 아니라, 다음 작업 판단에 필요한 핵심만 남긴다.

## 사용 방식

- Codex는 작업 시작 시 이 문서를 먼저 읽는다.
- UI/UX, 화면 설계, 기능 구현 작업이면 `work/plans/01_프로젝트 개요.md`도 함께 읽는다.
- 진행 상태가 필요하면 `work/plans/07_체크리스트형_개발_백로그.md`를 확인한다.
- UX 점검이 필요하면 `work/plans/12_UX_품질_체크.md`를 확인한다.
- 모바일 앱 전환 관련 판단이면 `work/plans/11_모바일_앱_전환_체크.md`를 확인한다.
- 긴 원문 문서는 필요할 때만 내려가서 확인한다.

## 반드시 지킬 것

- 화면은 사용자가 편하게 다음 행동을 찾는 것을 우선한다.
- 백오피스나 관리자 페이지 같은 화면 구성은 기본값으로 삼지 않는다.
- 테이블, 검색 필터, 엑셀식 목록은 필요하면 사용해도 되지만, 첫 화면의 핵심 경험을 가리지 않게 한다.
- 학생 화면은 감시나 평가보다 `지금 할 수 있는 가장 작은 다음 행동`을 우선한다.
- 부모 화면은 상세 로그보다 안심 요약과 개입 필요 여부를 우선한다.
- 실패 상황 문구는 처벌이나 통보가 아니라 회복, 줄이기, 내일로 옮기기 중심으로 쓴다.
- CRUD, 설정, 통계, 로그는 1차 화면이 아니라 보조 흐름으로 둔다.
- 웹앱으로 구현하더라도 모바일 앱 전환을 전제로 계산 로직과 UI 의존성을 분리한다.
- 실제 DB 변경 작업은 Codex가 직접 실행하지 않고, 필요한 SQL만 사용자에게 제공한다.

## 현재 상태

- 1차 MVP 구현과 검증 정리는 완료된 상태다.
- `work/plans/07_체크리스트형_개발_백로그.md` 기준으로 15단계 `MVP 검증`까지 체크되어 있다.
- Vercel preview 배포는 연결되어 있으며, 최신 push 후 자동 배포된다.
- 확정 시안 PNG만으로 CSS 재현을 진행한 결과 시각 품질이 떨어져, Figma형 디자인 스펙과 asset 기반 재구현으로 방향을 수정했다.
- 디자인 기준 문서: `work/design/00_figma_like_design_spec.md`
- asset/재구현 계획 문서: `work/design/01_asset_and_rebuild_plan.md`
- `public/assets/haruny` asset 폴더와 학생 `오늘`/`공부 중` 화면용 1차 SVG asset을 생성했다.
- 학생 `오늘` 화면과 `공부 중` 화면은 공통 UI 컴포넌트와 asset 기반으로 1차 재구현했다.
- 로컬 개발 서버는 `npm run dev -- --hostname 127.0.0.1 --port 3000` 방식으로 실행 가능하다.

## 구현된 큰 범위

- 학생 화면: 오늘, 이번 주, 오늘 줄이기, 하루 마감 흐름.
- 부모 화면: 안심, 오늘 계획 조정, 이번 주 조정, 하루 마감 요약, 알림 설정.
- 계획 화면: 시험 준비 만들기, 시험 과목/일차 입력, 준비안 확인.
- 평시 루틴 화면: 요일별 과목 루틴, 매일 반복 암기, 적용 기간 설정.
- 가족 설정 화면: 등교/하교, 학원, 식사, 취침 등 생활 리듬 설정.
- 도메인 로직: 장기 계획, 하루 코치, 평시 루틴, 가족 시간 계산, 알림 정책.
- 검증 문서: UX 품질 체크, 모바일 앱 전환 체크, MVP 검증 문서 작성.

## 작업 메모 규칙

- 모든 대화를 그대로 붙이지 않는다.
- 다음 작업 판단에 필요한 결정만 남긴다.
- 이미 백로그에 반영된 체크 항목은 길게 반복하지 않는다.
- 새로 확인한 사실은 파일, 커밋, 화면, 기능 기준으로 남긴다.
- 작업이 끝난 뒤 `현재 상태`와 `다음 후보 작업`을 우선 갱신한다.
- 문서가 길어지면 오래된 세부 설명은 원문 문서로 보내고, 이 문서에는 압축 요약만 남긴다.
