# 화면 시안 개발 참고

이 문서는 확정된 화면 시안을 이후 구현할 때 참고하기 위한 기준이다.
이미지는 분위기와 레이아웃 방향을 확인하는 용도이며, 실제 문구와 컴포넌트 구조는 제품 문서와 함께 맞춘다.

## 공통 원칙

- 모바일 우선 화면으로 구현한다.
- 첫 화면은 관리 화면이 아니라 현재 상태와 다음 행동을 보여준다.
- 테이블, 검색 필터, 수정/삭제 버튼, 통계 대시보드 느낌을 전면에 두지 않는다.
- 학생 화면은 잔소리나 감시가 아니라 회복 가능한 다음 행동을 제안하는 톤을 유지한다.
- 계산 로직은 UI 컴포넌트에 섞지 않고 별도 모듈 또는 서비스 계층에서 받는다.

## 01. 학생 `오늘`

- 확정 시안: `work/design/screens/01-student-today-selected.png`
- 상태: 확정

### 구현 핵심

- 앱을 열면 `지금 할 일`이 3초 안에 보여야 한다.
- 화면 중심은 전체 목록이 아니라 하나의 `다음 미션`이다.
- 핵심 선택지는 `바로 시작`과 `10분 쉬기`다.
- `10분 쉬기`는 회피가 아니라 짧게 쉬고 다시 시작하는 허용된 선택지로 보여준다.
- `회복 가능` 판단을 버튼 아래에 배치해 학생이 늦었다고 느끼지 않게 한다.
- 오늘 미션은 `필수`, `추가`, `남으면`으로 요약하고, 세부 목록은 전면에 길게 펼치지 않는다.
- 남은 시간은 `공부할 시간`과 `여유 시간`을 구분해 보여준다.
- 다음 일정은 하단에 짧게 배치한다.

### 화면 구조

1. 상단 제목: `오늘`
2. 격려 메시지 영역
3. 다음 미션 카드
4. 주요 선택 버튼: `바로 시작`, `10분 쉬기`
5. 회복 가능 상태
6. 오늘 미션 요약: `필수`, `추가`, `남으면`
7. 남은 시간 요약
8. 다음 일정

### 구현 시 피할 것

- 첫 화면에 오늘 공부 전체를 표나 긴 리스트로 보여주지 않는다.
- 완료율, D-day, 누적 미달량을 다음 미션보다 먼저 보여주지 않는다.
- 부모 감시나 실패 판정처럼 느껴지는 문구를 쓰지 않는다.
- `수정`, `삭제`, `관리` 같은 버튼을 전면에 두지 않는다.
- 시간표 전체를 빽빽하게 보여주지 않는다.

### 구현 메모

- 현재 시안의 캐릭터/일러스트는 필수 요소가 아니다. 구현에서는 과하지 않게 사용하거나 생략할 수 있다.
- 핵심은 일러스트보다 `다음 미션`과 `바로 시작 / 10분 쉬기`의 선택 구조다.
- 버튼은 터치하기 쉽게 크게 만들고, `바로 시작`을 명확한 1순위 액션으로 둔다.

## 02. 학생 `공부 중`

- 확정 시안: `work/design/screens/02-student-study-in-progress-selected.png`
- 상태: 확정

### 구현 핵심

- `오늘` 화면에서 `바로 시작`을 누른 뒤 이어지는 집중 화면이다.
- 현재 화면의 중심은 `현재 미션`, `남은 시간`, `끝냈어요`다.
- `잠깐 멈춤`은 보조 행동으로 유지하되, `끝냈어요`보다 약하게 보여준다.
- 미션 카드는 진행률이나 정답 개수 카운팅 없이 공부 항목 자체만 보여준다.
- 남은 시간은 큰 숫자와 단순한 진행 바로 표현한다.
- 하단에는 `끝나면 영어 단어`처럼 다음 행동을 가볍게 예고한다.

### 화면 구조

1. 상단 내비게이션: 뒤로가기, `공부 중`, 설정
2. 코치 격려 메시지
3. 현재 미션 카드
4. 남은 시간 카드
5. 주요 버튼: `끝냈어요`
6. 보조 버튼: `잠깐 멈춤`
7. 다음 행동 미리보기

### 구현 시 피할 것

- 원형 진행률, 퍼센트, `8/20` 같은 세부 진행 카운팅을 넣지 않는다.
- 도움 요청, 상세 로그, 성과 분석을 이 화면에 넣지 않는다.
- 현재 미션 외의 다른 미션 목록을 길게 보여주지 않는다.
- 타이머 화면을 시험 감독이나 감시처럼 보이게 하지 않는다.
- `잠깐 멈춤`이 `끝냈어요`와 같은 우선순위처럼 보이지 않게 한다.

### 구현 메모

- 첨부 시안의 우측 원형 카운트 영역은 제거된 상태가 기준이다.
- 미션 카드 오른쪽은 여백으로 두거나 작은 과목 아이콘 정도만 허용한다.
- `끝냈어요`를 가장 눈에 띄는 행동으로 두고, `잠깐 멈춤`은 낮은 대비의 보조 버튼으로 둔다.

## 03. 학생 `완료 응원 팝업`

- 확정 시안: `work/design/screens/03-student-completion-encouragement-modal-selected.png`
- 상태: 확정

### 구현 핵심

- 독립 페이지가 아니라 `끝냈어요` 클릭 직후 표시되는 모달 팝업이다.
- 팝업을 닫으면 `오늘` 화면으로 돌아가고, 다음 미션과 남은 시간은 재계산된 상태로 보여준다.
- 버튼은 `확인` 하나만 둔다.
- `5분 쉬기`, `다음 시작` 같은 선택지는 팝업에 넣지 않고 `오늘` 화면에서 처리한다.
- 팝업 레이아웃은 하나로 유지하고, 응원 메시지만 조건별 후보 중에서 바뀌게 한다.

### 화면 구조

1. 어둡게 처리된 `오늘` 화면 배경
2. 완료 아이콘 또는 작은 성공 일러스트
3. 응원 제목
4. 동적으로 바뀌는 응원 메시지 영역
5. 완료 요약: 집중 시간
6. 남은 상태 요약: 필수 미션 개수 등
7. 확인 버튼
8. 확인 후 `오늘` 화면으로 돌아간다는 짧은 안내

### 구현 시 피할 것

- 팝업 안에 쉬기/시작 선택 버튼을 넣지 않는다.
- 완료율, 랭킹, 점수, 상세 통계를 보여주지 않는다.
- 매번 같은 문구만 반복하지 않는다.
- 실패하거나 부족하다는 느낌의 문구를 쓰지 않는다.
- 팝업을 별도 라우트나 전체 화면 페이지로 만들지 않는다.

### 메시지 운영 메모

- UI는 하나만 만들고 메시지 후보를 여러 개 둔다.
- 일반 완료, 빠른 완료, 회복 가능, 마지막 필수 미션 완료 같은 조건별 메시지 묶음을 둔다.
- 같은 조건 안에서는 후보 문구 중 하나를 랜덤 또는 순환 방식으로 선택한다.

## 04. 학생 `하루 마감`

- 확정 시안: `work/design/screens/04-student-day-closing-selected.png`
- 상태: 확정

### 구현 핵심

- 하루를 실패/성공으로 판정하는 화면이 아니라, 오늘을 정리하고 내일 다시 이어갈 마음을 주는 화면이다.
- `끝낸 것`, `내일로 옮길 것`, `계획 현실성`, `코치 메시지`를 짧게 보여준다.
- 완료율이나 점수보다 마무리감과 회복 가능성을 우선한다.
- `내일로 옮길 것`은 실패가 아니라 자연스러운 조정으로 표현한다.
- `마감하기`를 1순위 행동으로 두고, `내일 보기`는 보조 행동으로 둔다.

### 화면 구조

1. 상단 제목: `하루 마감`
2. 오늘 마무리 메시지
3. 끝낸 것 목록
4. 내일로 옮길 것
5. 오늘 계획 현실성 판단
6. 코치 응원 메시지
7. 주요 버튼: `마감하기`
8. 보조 버튼: `내일 보기`

### 구현 시 피할 것

- 완료율, 점수, 랭킹을 화면 중심에 두지 않는다.
- 미완료 항목을 실패처럼 빨간색으로 강조하지 않는다.
- 상세 로그나 시간 기록을 길게 나열하지 않는다.
- 부모 감시 리포트처럼 보이게 만들지 않는다.
- `내일로 옮길 것`을 벌칙이나 경고처럼 표현하지 않는다.

### 구현 메모

- `오늘 계획은 조금 넉넉했어요`처럼 계획 자체의 현실성을 부드럽게 피드백한다.
- 학생용 문구는 짧고 안심되는 톤을 우선한다.
- 마감 후에는 오늘 상태를 닫고, 필요하면 내일 첫 행동을 미리 볼 수 있게 한다.

## 05. 학생 `이번 주`

- 확정 시안: `work/design/screens/05-student-this-week-selected.png`
- 상태: 확정

### 구현 핵심

- 주간 계획표나 캘린더가 아니라, 이번 주의 흐름을 코치 브리프처럼 보여준다.
- `계속할 것`, `이번 주 챙길 것`, `오늘 이어갈 것`의 세 묶음으로 구성한다.
- 학생에게 월간/주간 계획 전체를 관리하게 하지 않고, 오늘로 이어지는 첫 행동을 명확히 보여준다.
- 주간 보정 가능성을 `하루 못해도 주말에 보정 가능`처럼 안심되는 문구로 표현한다.
- 최종 행동은 `오늘로 이어가기`로 두고, 학생을 다시 `오늘` 화면의 실행 흐름으로 연결한다.

### 화면 구조

1. 상단 제목: `이번 주`
2. 이번 주 흐름 코치 메시지
3. 계속할 것: 매일 반복 루틴
4. 이번 주 챙길 것: 핵심 과목 2~4개
5. 오늘 이어갈 것: 오늘 첫 미션
6. 주말 보정 또는 무리 없음 안내
7. 주요 버튼: `오늘로 이어가기`

### 구현 시 피할 것

- 월간 캘린더나 날짜별 세부 계획표를 전면에 두지 않는다.
- 과목별 공부량을 표처럼 나열하지 않는다.
- D-day, 누적 미달량, 완료율을 화면 중심에 두지 않는다.
- 수정/삭제/관리 버튼을 이 화면에 노출하지 않는다.
- 부모나 관리자용 주간 계획 조정 화면처럼 보이게 만들지 않는다.

### 구현 메모

- 캘린더 없는 코치 브리프형을 기준으로 한다.
- 학생에게는 이번 주 전체보다 `오늘로 이어지는 첫 행동`이 더 중요하다.
- 장기 계획에서 내려온 과목은 `이번 주 챙길 것` 안에서 부담 없는 칩 형태로 보여준다.

## 06. 학생 `계획 조정 요청`

- 확정 시안: `work/design/screens/06-student-plan-adjustment-request-selected.png`
- 상태: 확정

### 구현 핵심

- 오늘 계획을 전부 끝내기 어려울 때 학생이 부모에게 조정을 요청하는 화면이다.
- 실패 신고가 아니라 회복 가능한 조정 요청으로 보여준다.
- 앱이 먼저 `추천 조정`을 제안하고, 학생은 이유를 짧게 선택한 뒤 요청한다.
- 추천 조정은 하나를 중심으로 보여주고, 화면을 복잡한 편집 양식으로 만들지 않는다.
- 부모에게 전달될 문구를 미리 보여줘 학생이 불안하지 않게 한다.

### 화면 구조

1. 상단 제목: `조정 요청`
2. 안심 메시지
3. 추천 조정 카드
4. 오늘 남은 실행안
5. 이유 선택 칩
6. 부모님께 보낼 내용 미리보기
7. 주요 버튼: `요청 보내기`
8. 보조 버튼: `취소`

### 구현 시 피할 것

- 빨간 경고나 실패 판정처럼 보이게 하지 않는다.
- 부모에게 혼나는 요청처럼 보이지 않게 한다.
- 여러 항목을 표처럼 편집하는 화면으로 만들지 않는다.
- `수정`, `삭제`, `관리` 같은 CRUD 용어를 전면에 두지 않는다.
- 장문의 사유 입력을 필수로 만들지 않는다.

### 구현 메모

- 추천 조정 예시는 `독서 20분 내일로 옮기기`처럼 구체적이고 작게 제안한다.
- 이유는 `시간 부족`, `피곤함`, `일정 변경`처럼 짧은 칩으로 선택한다.
- 부모에게 보낼 내용은 정중하고 간단한 문장으로 자동 생성한다.

## 07. 부모 `안심`

- 확정 시안: `work/design/screens/07-parent-reassurance-selected.png`
- 상태: 확정

### 구현 핵심

- 부모가 아이를 추궁하기 전에 현재 상태를 차분히 판단하는 홈 화면이다.
- 화면의 첫 답은 `기다려도 괜찮은가`, `개입이 필요한가`, `회복 가능한가`여야 한다.
- 상세 로그보다 개입 판단과 안심 요약을 먼저 보여준다.
- 부모 화면이지만 감시 대시보드처럼 보이지 않게 한다.
- `지금은 대기`, `필요하면 응원`, `반복 지연 시 조정`처럼 부모 행동 기준을 부드럽게 제시한다.

### 화면 구조

1. 상단 제목: `안심`
2. 자녀/오늘 상태 선택
3. 현재 판단 메시지
4. 오늘 공부 진행 요약
5. 개입 판단 가이드
6. 회복 가능 여부
7. 다음 일정
8. 주요 버튼: `오늘 상태 보기`
9. 보조 버튼: `알림 기준 보기`

### 구현 시 피할 것

- 첫 화면에 상세 로그나 감시 기록을 길게 나열하지 않는다.
- 위치, 휴대폰 사용, 실시간 감시처럼 보이는 요소를 넣지 않는다.
- `미달`, `지연`, `실패` 같은 불안 조장 표현을 전면에 두지 않는다.
- 부모가 바로 연락하거나 추궁하게 만드는 문구를 쓰지 않는다.
- 통계 차트나 완료율 그래프를 화면 중심에 두지 않는다.

### 구현 메모

- 부모에게는 `기다려도 됨`을 명확히 알려주는 것이 중요하다.
- `오늘 상태 보기`는 상세 화면으로 들어가는 보조 흐름이지 첫 화면의 중심이 아니다.
- 알림 기준은 부모가 과잉 알림을 줄일 수 있게 하는 2차 흐름으로 둔다.

## 08. 부모 `하루 마감 요약`

- 확정 시안: `work/design/screens/08-parent-day-end-summary-selected.png`
- 상태: 확정

### 구현 핵심

- 부모가 하루 끝에 아이를 추궁하지 않고, 무엇을 칭찬하고 무엇을 내일 조정할지 보는 화면이다.
- 상세 기록보다 `끝낸 공부`, `내일로 옮긴 것`, `내일 첫 행동`, `칭찬할 점`, `계획 현실성`을 우선한다.
- `내일로 옮긴 것`은 실패가 아니라 자연스러운 조정으로 표현한다.
- 부모에게 아이에게 말할 첫 문장을 제안해준다.
- 다음 행동은 `내일 보기`를 1순위로 둔다.

### 화면 구조

1. 상단 제목: `하루 마감`
2. 자녀/날짜 정보
3. 오늘 마감 요약 메시지
4. 끝낸 공부
5. 내일로 옮긴 것
6. 내일 첫 행동
7. 부모 칭찬 가이드
8. 계획 현실성 판단
9. 주요 버튼: `내일 보기`
10. 보조 버튼: `오늘 자세히`

### 구현 시 피할 것

- 완료율, 점수, 랭킹, 성과표처럼 보이게 하지 않는다.
- 미완료 항목을 빨간 경고로 강조하지 않는다.
- 상세 로그를 첫 화면에 길게 나열하지 않는다.
- 부모가 바로 추궁하도록 만드는 문구를 쓰지 않는다.
- 감시 리포트나 관리자 보고서처럼 보이게 만들지 않는다.

### 구현 메모

- 부모용 마감 문구는 `칭찬은 시작한 점부터`처럼 대화에 바로 쓸 수 있게 만든다.
- 계획 현실성은 `조금 넉넉했음`, `무리 없음`처럼 부드럽고 짧게 표현한다.
- `오늘 자세히`는 필요할 때만 들어가는 2차 흐름이다.

## 09. 부모 `오늘 계획 조정`

- 확정 시안: `work/design/screens/09-parent-today-plan-adjustment-selected.png`
- 상태: 확정

### 구현 핵심

- 부모가 오늘 계획을 직접 관리하는 화면이 아니라, 오늘 계획이 현실적인지 확인하고 필요한 최소 조정을 적용하는 화면이다.
- 앱의 조정안은 AI 자유 판단이 아니라 남은 시간, 남은 공부량, 일정, 미션 단계에 따른 계산 기반 제안이다.
- `추천 조정` 표현은 구현 시 `오늘에 맞춘 조정안` 또는 `현실적인 조정안`으로 다듬을 수 있다.
- 한 번에 여러 항목을 편집하게 하지 말고, 가장 효과적인 조정 하나를 먼저 보여준다.
- 조정 후 학생 화면에 어떻게 보일지 미리 보여준다.

### 화면 구조

1. 상단 제목: `오늘 계획 조정`
2. 자녀/날짜 정보
3. 오늘 계획 현실성 메시지
4. 남은 가능 시간과 남은 공부 시간
5. 오늘에 맞춘 조정안
6. 오늘 조정 후 계획 미리보기
7. 고정 일정
8. 주요 버튼: `조정안 적용`
9. 보조 버튼: `그대로 두기`

### 구현 시 피할 것

- 공부 항목을 표처럼 나열하고 수정/삭제 버튼을 반복하지 않는다.
- 부모가 모든 항목을 세밀하게 관리하는 CRUD 화면으로 만들지 않는다.
- AI가 판단했다는 식의 과장된 표현을 쓰지 않는다.
- 빨간 경고나 실패 판정으로 조정을 압박하지 않는다.
- 학생 화면과 동떨어진 부모용 관리 UI처럼 보이지 않게 한다.

### 구현 메모

- 계산 기준은 `남은 가능 시간`, `남은 공부 시간`, `고정 일정`, `필수/추가/남으면` 미션 단계다.
- 조정안 예시는 `독서 20분을 내일로`처럼 구체적이고 작은 단위로 제안한다.
- 적용 후에는 학생의 `오늘` 화면에서 다음 미션과 남은 시간이 재계산되어야 한다.
