# 하루니 Figma형 디자인 스펙

이 문서는 `work/design/screens/*-selected*.png` 확정 시안을 기준으로 구현 가능한 디자인 기준을 정리한다.
실제 Figma 파일을 복원하는 문서가 아니라, 개발자가 Figma를 보는 것처럼 레이어, 컴포넌트, 토큰, asset 기준을 파악하기 위한 스펙이다.

## 기준과 원칙

- `work/design/screens/*-selected*.png`는 확정 시안이다.
- 구현은 시안의 정보 우선순위, 레이아웃 밀도, 여백, 카드 질감, 일러스트 품질을 따른다.
- 텍스트, 버튼, 상태값, 데이터는 코드와 실제 데이터로 렌더링한다.
- 캐릭터, 책, 집, 달, 컵, 노트, 장식 요소처럼 시각 품질이 중요한 요소는 CSS로 억지로 그리지 않고 asset으로 분리한다.
- 화면 전체 PNG를 배경으로 깔아 데모처럼 보이게 만들지 않는다.
- mock 데이터가 바뀌어도 화면 구조가 무너지지 않아야 한다.
- 모바일 앱 전환을 전제로, 화면은 390px~430px 폭에서 먼저 완성한다.

## 모바일 캔버스

- 기준 폭: 390px, 430px
- 최소 대응 폭: 360px
- 최대 콘텐츠 폭: 430px
- 페이지 좌우 padding: 24px 기준, 작은 폭에서는 20px 허용
- 상단/하단 기본 여백: 28px
- 섹션 간 간격: 20px~24px
- 주요 액션 하단 고정 느낌은 유지하되, 실제 position fixed는 화면별로 필요한 경우만 쓴다.

## 버튼

### 주요 행동

- 색상: `#ff5a4f`
- 텍스트: 흰색, 24~30px, 900
- 높이: 64px 이상
- radius: 18~24px
- 아이콘: 흰 원 안 체크/플레이 등 asset 또는 정교한 SVG 사용

### 보조 행동

- 색상: 연청록 배경 `#eefafa`
- 텍스트: `#19a9a8`
- 높이: 56px 이상
- 주요 행동보다 낮은 대비를 유지한다.

## Asset 정책

- asset 루트: `public/assets/haruny`
- 화면별 asset은 `public/assets/haruny/screens/{screen-id}/`에 둔다.
- 공통 asset은 `public/assets/haruny/common/`에 둔다.
- PNG/WebP를 우선 사용하고, 단색 선 아이콘은 SVG도 허용한다.
- asset은 투명 배경을 기본으로 한다.
- 시안에서 텍스트가 포함된 영역은 asset으로 쓰지 않는다.
- CSS로 만든 임시 일러스트는 최종 구현에서 제거한다.

## 공통 컴포넌트 분해

### AppFrame

- 모바일 앱 같은 단일 열 레이아웃
- 최대 폭 430px
- 배경 `background`
- 화면별 하단 CTA가 있는 경우 마지막 섹션 아래 여백을 넉넉히 둔다.

### ScreenHeader

- 왼쪽: 화면 제목 또는 뒤로가기
- 가운데 제목이 필요한 화면: `공부 중`
- 오른쪽: 작은 얼굴/설정/닫기 액션

### HeroMessageCard

- 연녹색 배경
- 왼쪽 문구, 오른쪽 일러스트 asset
- 학생 화면은 격려 톤, 부모 화면은 안심 톤

### PrimaryMissionCard

- 현재 또는 다음 행동 하나만 강조
- 왼쪽/오른쪽에 학습 asset
- 과목명, 예상 시간, 세부 과제 순서

### ActionPair

- 왼쪽 주요 행동, 오른쪽 보조 행동
- 모바일 폭에서도 두 버튼 텍스트가 줄바꿈으로 깨지지 않아야 한다.

### SummaryMetricCard

- 2~3개의 요약 값
- 세부 목록이 아니라 상태 요약을 보여준다.

### CoachMessageCard

- 학생 캐릭터 asset과 짧은 코치 메시지
- 실패/부족 문구보다 회복/마감/다음 행동 중심

## 구현 금지/주의

- 확정 시안의 고품질 일러스트를 CSS 도형으로 대체하지 않는다.
- 화면 전체 PNG를 깔고 클릭 영역만 얹는 방식은 쓰지 않는다.
- 텍스트를 이미지에 박지 않는다.
- 빨간색은 실패/경고보다 주요 행동에 우선 사용한다.
- 완료율, 점수, 순위, 미달량은 학생 화면 중심에 두지 않는다.
- 주요 버튼이 360px 폭에서 두 줄 이상 어색하게 깨지면 크기/구조를 조정한다.

## 구현 검증 기준

- 390px 폭에서 시안과 정보 순서가 일치한다.
- 첫 화면에서 가장 중요한 행동이 3초 안에 보인다.
- asset 없이 CSS로 그린 임시 일러스트가 남아 있지 않다.
- 긴 이름/과목명에도 버튼과 카드가 깨지지 않는다.
- Vercel 배포 화면에서 실제 휴대폰으로 확인한다.
